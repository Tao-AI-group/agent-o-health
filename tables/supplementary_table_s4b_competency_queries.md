# Supplementary Table S4B. Detailed AGENT-O competency-question results

The 12 natural-language competency questions were implemented as executable
SPARQL `SELECT` queries. Queries were executed over the integrated ontology,
alignment files, application profiles, and example RDF graphs after OWL-RL
reasoning. The query graph contained 3,644 input triples and 6,364 additional
inferred triples. A competency question was considered answered when its query
returned at least one row containing the prespecified evidence type. Full query
text and machine-readable results are provided in `queries/competency/` and
`outputs/sparql/cq_results.json`, respectively.

| CQ ID | Natural-language competency question | SPARQL query file | Expected evidence | Actual result/evidence | Status |
| --- | --- | --- | --- | --- | --- |
| CQ1 | Which versioned model specification realizes each model component, what role does it play, what descriptive fields characterize it, and which deployment was used at runtime? | `cq_model_specification_deployment.rq` | Agent, model component and role, model identifier/version/type, developer, input/output specifications, capability, intended use, limitation, deployment, and provider | 3 rows. Retrieved the Medication Safety, EHR Medication Review, and Diagnostic agent systems with their component roles, versioned model specifications, interface specifications, and runtime deployments. | Answered |
| CQ2 | Can agent-level inputs, model deployments, generated model outputs, and final agent actions be distinguished? | `cq_model_interface_layers.rq` | Agent and execution run linked separately to input artifact, model deployment/specification, generated model output, and final agent output/action | 4 rows. Retrieved three FHIR-aligned medication-review inputs and one diagnostic input, each linked through a model deployment and generated model output to a distinct final recommendation. | Answered |
| CQ3 | What are the intended user, population, setting, specialty, condition, workflow stage, task, intended action, decision role, deployment mode, and excluded or prohibited uses of a clinical agent use case? | `cq_clinical_intended_use.rq` | Agent and clinical use case with the complete intended-use context and use constraints | 4 rows. Retrieved the Medication Safety use case for two intended-user roles and the EHR Medication Review and Diagnostic use cases, including population, setting, task, intended action, decision role, deployment mode, and prohibited/out-of-scope uses. | Answered |
| CQ4 | Which inputs are aligned with FHIR resources, profiles, formats, and terminology systems, and how are they connected to agents or recommendations? | `cq_fhir_inputs.rq` | FHIR-aligned input, resource type/IRI, FHIR profile, data format, terminology system, and related agent or recommendation | 3 rows. Retrieved Condition, Patient, and MedicationRequest inputs with their FHIR profiles, FHIR JSON format, SNOMED CT or RxNorm terminology, and downstream medication-safety recommendation. | Answered |
| CQ5 | Which datasets have data-use conditions, permissions, restrictions, or governing policies? | `cq_data_use_permissions.rq` | Dataset linked to data-use condition, permission, restriction, or policy | 1 row. | CQ6 | Which automation, accountability, policy, risk, review, fallback, escalation, monitoring, and compliance elements are represented for clinical agents? | `cq_governance_profile_checklist.rq` | Clinical agent with governance-profile entities, including automation level, accountability role, risk, review requirement, monitoring, and available policy/control elements | 3 rows. | CQ9 | Which source entities support a proposed action, which execution or tool activity generated each source, who was associated with that activity, and which metric result came from the same run? | `cq_prov_trace.rq` | Proposed action linked to supporting source entity, generating execution/tool activity, associated agent, and evaluation result when available | 3 rows. | CQ10 | Which assessor, report, profile, rubric/prompt versions, evidence, and human-verification status produced a reporting assessment? | `cq_reporting_assessment_provenance.rq` | Assessment activity, assessor, report, profile, rubric and prompt versions, assessment dimension, supporting evidence, and verification status | 5 rows. **Overall result:** 12/12 competency queries were answered.
